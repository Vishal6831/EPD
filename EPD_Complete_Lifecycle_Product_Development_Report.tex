\section*{Abstract}
This report documents the end-to-end product development lifecycle of \textbf{SMARTCLASS AI}, an edge-computing and Internet of Things (IoT) integrated smart classroom management system engineered to eliminate manual attendance overhead, track student cognitive engagement, and maintain optimal indoor environmental and fire safety conditions in high-density educational spaces. The system addresses the limitations of conventional roll-call and cloud-tethered IoT devices, which suffer from proxy attendance, recurring subscription fees, and prohibitive privacy and bandwidth liabilities.

The engineered solution couples an ultra-low-power \textbf{ESP32 microcontroller subsystem} (interfacing DHT11, MQ-135, and PIR sensors with an isolated relay driver) to a local \textbf{Edge AI computing node} running lightweight 478-point facial landmark regression (Google MediaPipe) and 128-dimensional deep face metric learning (\texttt{dlib} / \texttt{face\_recognition}). Environmental telemetry and vision analytics are consolidated seamlessly into a responsive \textbf{Next.js 14 / TypeScript} digital-twin dashboard over local Wi-Fi via RESTful JSON services.

Rigorous verification tests demonstrate nominal 3.30 V power rail stability ($\pm 0.3\%$ regulation error), rapid actuation latency ($42.4\text{ ms}$ vs. $100\text{ ms}$ ceiling), 99.8\% packet delivery under stress, and persistent attendance registration with automated distance-to-confidence scaling ($>90\%$ confidence). The system conforms strictly to IEEE Std 29148 requirements engineering, IEC 60617 schematic standards, ISO 7200 drawing sheet metadata, and IPC-2221 Class 2 design guidelines for a 2-layer FR-4 PCB. With a total prototype Bill of Materials (BOM) cost of \text{INR 1,848.00}, SMARTCLASS AI achieves substantial commercial and economic viability for institutional deployment.

\section{Software and Firmware Block Diagram}
\traceto{\texttt{REQ-01}, \texttt{REQ-02}, \texttt{REQ-03}, \texttt{REQ-06}, \texttt{REQ-08} — firmware drivers, state machine sequencing, and local Edge AI integration.}

\subsection{Representative Firmware Code Excerpt}

\begin{lstlisting}[language=C++]
// SMARTCLASS AI - ESP32 FIRMWARE TELEMETRY & CONTROL EXCERPT
// Realizes REQ-01 (Sensing), REQ-02 (Actuation), and REQ-03 (Wi-Fi Telemetry)
void appControlTask(void *pvParameters) {
    for (;;) {
        float tempVal = dht.readTemperature();
        float humidityVal = dht.readHumidity();
        float gasPpm = readFilteredGasADC();
        bool motionDetected = digitalRead(PIR_PIN);

        // Closed-loop threshold actuation
        if (tempVal > 28.0 || gasPpm > 1000.0) {
            digitalWrite(RELAY_PIN, HIGH); // Optocoupler ON -> Fan ON
        } else {
            digitalWrite(RELAY_PIN, LOW);
        }

        // Publish JSON packet to Next.js API
        if (WiFi.status() == WL_CONNECTED) {
            HTTPClient http;
            http.begin("http://192.168.43.150:3000/api/sensors");
            http.addHeader("Content-Type", "application/json");
            
            StaticJsonDocument<256> doc;
            doc["temperature"] = tempVal;
            doc["humidity"] = humidityVal;
            doc["co2"] = gasPpm;
            doc["motion"] = motionDetected;
            
            String payload;
            serializeJson(doc, payload);
            http.POST(payload);
            http.end();
        }
        vTaskDelay(pdMS_TO_TICKS(2000)); // Sample every 2.0 s
    }
}
\end{lstlisting}

\subsection{Current Hardware Prototype Realisation Status}
\noindent\textbf{Fabrication Status Note:} The complete 2-layer PCB layout, trace geometry sizing per IPC-2221B, clearance isolation slot routing ($>6.0\text{ mm}$ creepage), and RS-274X Gerber photoplot exports were 100\% completed in KiCad / EasyEDA. 

Because commercial chemical etching and printed board fabrication require a multi-week manufacturing window currently queued with the fab vendor, an equivalent physical hardware prototype was constructed on a high-density prototyping breadboard/perfboard assembly. This prototype faithfully replicates the exact schematic topology, trace impedance paths, decoupling capacitor placements, and galvanic optocoupler isolation boundaries defined in the PCB CAD layout. This enabled thorough laboratory verification (\S18) of all sensory acquisition, microcontroller processing, and relay actuation circuits prior to receiving the etched PCB boards.
